# 第 2 层 · 通信层详解（requests/）

> 展开 `rules.md`「第 2 层 通信层」：状态板结构、单一 owner 免锁、状态优先、@请求 / 认领 / 回报。
> 简洁规则见 [`rules.md`](../rules.md)。

---

## 2.1 作用

`requests/` 是 agent 之间**唯一的异步通信渠道**：广播自己要做什么、向别人发请求、认领任务、回报进度。每个 agent 一个文件：`requests/agent_A.md` / `agent_B.md` / `agent_C.md`。

## 2.2 单一 owner = 免锁

- **只有你本人写自己的** `requests/agent_<你>.md`，别人只读。
- 因此请求区**不需要加锁**、天然无冲突（这也是它永不与人冲突、可作回退兜底的原因，见 `docs/5-concurrency.md` 5.7）。
- 要回应别人，在**你自己的**文件里写，**绝不去改对方的文件**。

## 2.3 状态板结构（`requests/agent_<你>.md`）

```
## 我是谁 / 负责方向
## 当前状态
- 正在做：<将做/正在做的事 + 目标路径>
- 持有的锁：<资源 + 路径 + 时间戳，或「无」>
- 阻塞 / 等待：<在等谁、等什么，或「无」>
## 我发出的请求（等待他人认领）
## 我认领的任务（来自他人请求）
## 完成回报（通知发起方）
```

## 2.4 状态优先（硬性顺序，最重要）

- 写任何共享内容**之前**，先把「你要做什么」写进「当前状态 · 正在做」，**和加锁合并成一个 commit push 出去**。
- 做完在最后一次 push 里把状态改为进度或删回「空闲」。
- **绝不允许先写内容、后补状态**——否则队友的前置检查（`git pull` 后读 requests）看不到你的意图，易重复劳动或撞车。
- 纯读取、不产出内容时**无需报状态**（0 push）。

## 2.5 请别人做事 / 认领 / 回报（格式 + 例子）

- **发请求**：在自己的文件里追加一行 `@` 目标 agent：
  ```
  - [2026-09-09T14:30Z] @agent_B 请把 results/fig3.png 重画成 300dpi  状态:待认领
  ```
- **发现指派给自己的**：定期读三个 `requests/*.md`（读请求区**免锁**），看到 `@你` 且「待认领」的，就在**你自己的**文件里登记认领与进度：
  ```
  - [2026-09-09T14:35Z] 来源@agent_A 重画 fig3.png 为 300dpi  进度:进行中
  ```
- **完成后回报**：也在**你自己的**文件里写一行通知发起方，发起方轮询得知。**不要改对方的文件**：
  ```
  - [2026-09-09T15:00Z] @agent_A 你要的高清图已完成，见 results/fig3.png
  ```
