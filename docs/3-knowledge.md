# 第 3 层 · 知识层详解（discussion/）

> 展开 `rules.md`「第 3 层 知识层」：三个讨论文件的用途、只追加规范、决策记录格式、改协议流程。
> 简洁规则见 [`rules.md`](../rules.md)。

---

## 3.1 作用与三个文件

`discussion/` 是全队**共享的知识沉淀区**，把分散在各机的思考汇成一处：

- `problem.md`：题目理解与拆解。
- `ideas.md`：思路 / 方法（只追加）。
- `decisions.md`：已定决策与理由（只追加）。

## 3.2 读写规则

- **读**讨论区：免锁，只查 `locks/discussion.lock` 里目标文件有无活跃 `W` 锁（有则等对方改完再 pull 最新读）。
- **写**讨论区：拿对应路径的写锁 `W`（详见 `docs/5-concurrency.md`）。

## 3.3 只追加、不改他人

- **只追加，不改写 / 删除他人条目**。
- 每条署名 + UTC 时间戳：
  ```
  ## [agent_A 2026-09-09T14:30Z] 建议用元胞自动机建模车流
  理由：……
  ```

## 3.4 decisions.md 决策记录格式

已定决策每条**四段式**：
```
## D<编号> [时间戳UTC] 决策标题
- 决策：……
- 理由：……
- 参与者：……
- 影响：……
```
- 定了就别反复推翻；要改需**追加新条目**说明原因，**不删旧的**。
- 决策索引：D0 读写锁+单一 owner · D1 AGENTS 入口+rules 权威 · D2 路径级多行锁 · D3 前置检查 · D4 状态优先 · D5 废读锁+合并 push+读免锁 · D6 协议重构为 5 层 + 简洁/详解分离 · D9/D10 通信闭环与归档 · D11 最终论文写作与质量规则。

## 3.5 改协议的流程

1. 修改协作规范（`rules.md` / `AGENTS.md` / `docs/` 等）**前**，先在 `decisions.md` 追加一条 `D<编号>` 记录共识（决策 / 理由 / 参与者 / 影响）。
2. 再改协议文件，并通知全部 agent（在各自 `requests/` 状态板可见）。
3. 改**根协议文件**（rules.md/AGENTS.md/README.md/docs/，不属于四个可锁资源）时，用**整把 discussion 写锁**（省略路径）作代理保护（见 `docs/5-concurrency.md` 5.3）。
